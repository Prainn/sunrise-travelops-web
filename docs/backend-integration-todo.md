# Sunrise TravelOps 前端接入后端待办

更新日期：2026-08-31

## 已确认边界

- 前端原型自动按 10% 目标利润率生成建议成人价；手工修改后改用用户价格。
- Costing Sheet/Line、Quote/Version/Line、版本锁定和不可变快照由后端实现。
- 当前 PDF 暂由前端生成并记录报价生成时间。正式版本改为后端基于锁定 Quote Version 生成、保存和返回 PDF，并记录文件哈希、生成人、服务端生成时间及历史文件。
- 状态变化、审计日志和版本快照必须由后端在同一数据库事务内原子完成；前端只调用一个业务命令接口并使用服务端返回结果刷新界面。
- 前端权限矩阵按“资源域 + list/create/update/delete”收口；后端必须重复校验角色、动作和数据范围。

## 前端待办

### 1. 拆分接口类型与页面表单类型

- 按领域建立 API 的 list item、detail、create input、update input、query、page result 类型。
- 页面 Form 类型只描述可编辑字段，不直接复用 API Detail，也不携带服务端生成字段。
- 在 service 层集中完成 API 数据到页面模型的映射，避免页面散落字段兼容逻辑。

### 2. 建立统一请求客户端

- 统一 base URL、超时、认证头、刷新令牌单飞、取消请求和错误映射。
- 统一分页、筛选、排序和响应解包。
- 对创建版本、生成 PDF 等命令支持幂等键和重复提交保护。
- 页面只能调用领域 service，不直接调用 `fetch` 或具体请求库。

### 3. 统一金额和时间契约

- 与后端确认金额传输格式：人民币两位小数，建议 API 使用十进制定点字符串；前端计算继续使用整数分，边界处统一转换。
- 明确利润率的小数精度、四舍五入顺序，以及 10% 建议价由后端重新计算并返回最终值。
- 时间点使用带时区的 ISO 8601；日期字段使用 `YYYY-MM-DD`，不得混用本地日期时间字符串。
- 服务端保存 UTC 时间点，前端按业务时区展示；PDF 使用后端返回的可信生成时间。

## 前端基线回归

1. 固定 Node/pnpm 版本并执行 `pnpm install --frozen-lockfile`。
2. 依次执行 `pnpm type-check`、`pnpm test`、`pnpm lint`、`pnpm build`，保存命令、版本和结果。
3. 建立四类角色账号的权限矩阵回归：菜单可见性、按钮可见性、越权入口和只读状态。
4. 建立主链路手工用例：登录 → 资源维护 → 创建询盘 → 创建/复制 Draft → 编辑每日资源 → 验证 10% 建议价 → 手工改价 → PDF 预览/取消/确认下载 → Quoted 只读 → 查看日志。
5. 为每条用例固定 mock 输入和预期状态、金额、日志条数、PDF 关键文本，并保留截图或录屏证据。
6. 优先把登录、询盘到报价 PDF 主链路补为 Playwright E2E；后端接入后以同一批用例做契约与回归验收。
