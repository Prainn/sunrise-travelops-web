# Sunrise TravelOps P0 需求说明

版本：v1.3
更新日期：2026-08-31

## 已确认的报价与后端边界

- 系统按 10% 目标利润率自动生成建议成人价；用户手工修改后，以修改后的成人价继续计算。儿童价固定为成人价的 70%。
- Costing 和 Quote 的实体、版本、快照、锁定与追溯由后端实现。
- 当前 PDF 暂由前端生成并在文件内记录报价生成时间；确认下载后，前端原型同步记录该时间。
- 后续 PDF 改为后端从锁定 Quote Version 生成并保存，记录文件哈希、生成人、服务端生成时间，并支持历史文件原样下载。
- 状态变更、审计日志写入、Costing/Quote 版本快照由后端在同一数据库事务内完成。

前端接入后端前的工程待办统一记录在 `docs/backend-integration-todo.md`。

## P0 范围：询盘日志

### 列表入口

- 询盘列表最后一列名称为“行程”。
- 该列显示“行程管理”和“询盘日志”两个入口。
- 点击“询盘日志”进入当前询盘的独立日志页面。

### 记录范围

P0 必须记录以下七类操作：

1. 创建询盘。
2. 编辑询盘。
3. 创建行程，包括复制为新 Draft。
4. 编辑行程，以用户点击“保存”为记录时机。
5. 行程生成 PDF，以确认下载并成功完成状态转换为记录时机。
6. 归档询盘。
7. 流失询盘。

取消操作、校验失败、PDF 仅生成预览但未确认下载时不记录成功日志。一次询盘编辑同时产生流失状态变化时，分别记录“编辑询盘”和“流失询盘”。

### 日志展示

- 日志按操作时间倒序展示。
- 展示操作时间、操作类型、操作人姓名和账号。
- 行程类操作展示行程编号和标题。
- 流失操作展示流失原因。
- 已归档、已流失询盘的日志仍可查看。

### Draft 保存

- “保存”按钮位于“生成 PDF”按钮旁。
- 仅当当前行程为可编辑 Draft，且当前用户拥有对应内容或价格编辑权限时显示。
- 每次点击保存都更新行程 `updatedAt` 并记录“编辑行程”。
- 保存不生成 PDF、不改变行程状态；本阶段不记录编辑前后 diff。

### 当前数据边界

- 日志类型独立定义，mock 记录保存在 `src/data/data.ts`。
- 页面通过 `inquiry-log.service.ts` 查询和新增日志，不直接维护日志数组。
- 运行时新增日志刷新页面后恢复初始 mock 数据，与当前询盘和行程原型一致。
- P0 不包含后端持久化、日志分页筛选、日志导出、快照或 diff。

## 验收标准

- 七类操作均能产生内容正确且不重复的日志。
- 不同询盘之间日志数据隔离。
- Draft 保存后仍为 Draft，PDF 确认下载后才转为 Quoted。
- 日志中的当前操作人来自登录用户信息。
- 中英文界面、类型检查、单元测试、Lint 和生产构建通过。
