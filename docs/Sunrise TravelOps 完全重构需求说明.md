# Sunrise TravelOps 完全重构需求说明

版本：v1.3
更新日期：2026-08-31

## 报价与 PDF 过渡方案

- 当前前端按 10% 目标利润率自动生成建议成人价；用户手工修改后，以修改后的成人价继续计算。儿童价固定为成人价的 70%。
- Costing Sheet、Costing Line、Quote、Quote Version 和 Quote Line 由后端实现，前端当前计算结果仅用于原型交互，不作为生产报价版本。
- 当前 PDF 暂由前端生成，PDF 内记录报价生成时间，确认下载后将该时间记录在行程中。
- 后续正式方案改为后端基于锁定的 Quote Version 生成并保存 PDF，同时记录文件哈希、生成人和服务端生成时间，支持历史文件原样下载。
- 状态变更、审计日志写入和 Costing/Quote 版本快照必须由后端在同一数据库事务内完成；前端不得分别提交这些结果来模拟原子性。

前端接入后端前的工程待办统一记录在 `docs/backend-integration-todo.md`。

## 询盘操作日志

系统应为每个询盘维护不可变的操作日志，并覆盖询盘及其关联行程的关键业务操作：

- 创建询盘、编辑询盘、归档询盘、流失询盘。
- 创建行程、编辑并保存 Draft 行程、生成行程 PDF。
- 通过复制已有行程创建新 Draft 时，记录为创建行程，并标识创建方式为复制。

日志至少保存询盘、操作类型、操作时间、操作人、目标实体及目标编号。行程类日志必须保存行程 ID 和行程编号；流失询盘应保存流失原因。

询盘列表的“行程”列应同时提供“行程管理”和“询盘日志”入口。已归档或已流失的询盘仍可查看日志。

## 行程保存与审计边界

Draft 行程应支持独立保存，不生成 PDF，也不改变 Draft 状态。每次用户明确点击保存都应产生一条“编辑行程”日志。

行程编辑差异不是当前版本的实现范围，但保存动作是后续差异审计的稳定边界。后续日志模型需要支持保存编辑前后快照或结构化 diff，包括行程基础信息、每日安排、资源项目、数量和价格变化。

## 后端接入要求

前端原型通过日志 service 读写 mock 数据。接入后端后，页面和流程编排层保持现有调用边界，由 API 替换 mock service 的数据访问实现。

生产环境的日志必须由服务端在业务事务成功后写入，不以客户端提交的操作人和操作时间作为可信审计依据。日志应只允许查询，不允许普通业务用户修改或删除，并支持分页、按操作类型筛选和长期追溯。
