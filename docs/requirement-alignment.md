核对日期：2026-08-26

## 结论

两份需求文档描述的是完整产品目标，当前代码是仅使用前端 mock 数据的 P0 交互原型。涉及“当前是否已经实现”时，以代码为准；文档中的未实现内容继续作为目标需求，不应被表述成现有能力。

当前已打通的主要原型链路是：旅行社资源 → 询盘 → 多个独立行程 → 每日资源与价格 → 生成并下载中文报价 PDF。

## 实现对照

| 模块 | 当前代码实现 | 与需求的关系 |
|---|---|---|
| 登录、用户与权限 | 有 mock 登录、用户维护、前端角色和按钮权限 | 部分实现。没有后端鉴权、角色管理、数据范围、登录审计和安全策略 |
| 系统配置 | 有字典、业务分类、资源计价单位和交通方式 | 部分实现。没有编号规则、时区及完整系统参数配置 |
| 旅行社与询盘 | 支持旅行社选择、联系人带出、负责人、操作计调、筛选、编辑、归档和状态限制 | 核心原型已实现。跟进记录、附件、转移记录和审计未实现 |
| 资源主数据 | 有旅行社、地接社、酒店及房型、餐厅、景点、车辆、导游；报价可区分直营或指定地接社 | 部分实现。司机、车辆司机绑定、独立房型页面和导入未实现；导游当前把报价来源直接放在导游记录上 |
| 行程 | 支持一个询盘下多个独立行程、复制行程、每日安排、复制天、排序和选择资源报价 | 部分实现。当前资源 Item 只有酒店、景点、餐厅、车辆、导游；状态只有 Draft、Ready for Costing、Quoted、Archived |
| 成本与报价 | 行程 Item 保存资源成本和手工填写的对客单价，页面实时汇总成本、售价、利润和毛利率 | 简化原型。没有 Costing Sheet、Quote、Quote Version、快照和统一加价规则 |
| 报价 PDF | 校验空白行程天和缺失售价，预览后下载中文 PDF，并将行程标记为 Quoted | 简化原型。PDF 直接从行程生成；没有中英文选择、版本历史、文件哈希和历史文件下载 |
| 审计与附件 | 未实现 | 与 P0 目标有明确差距 |
| 工作台 | 有通用 Dashboard | 不是需求中按收客计调、操作计调区分的岗位工作台 |
| API、安全、备份与监控 | 当前为纯前端 mock | 不属于当前仓库已实现能力，需要后端项目承接 |

## 代码优先的当前业务规则

- 询盘状态为 `new`、`planning`、`quoted`、`lost`、`archived`。
- `lost` 和 `archived` 询盘只读；归档入口不物理删除询盘。
- 创建或复制 Draft 行程会把活动询盘调整为 `planning`。
- 下载报价 PDF 后，行程变为 `quoted`，询盘变为 `quoted`。
- 已报价行程不可直接编辑，需要复制为新的 Draft 行程。
- 操作计调维护行程内容并生成 PDF；收客计调维护询盘和对客售价。
- 资源成本来自所选资源报价；当前对客售价由收客计调逐项填写，不是统一加价规则自动计算。
- 所有业务数据当前只保存在 `src/data/data.ts` 的前端 mock 数据及运行时内存中。

## 后续实现时必须保留的差距

以下内容仍是需求目标，不能因为当前原型未实现而从需求中删除：

- Costing Sheet、Quote 和 Quote Version 的独立实体、快照、锁定与追溯。
- PDF 版本文件、哈希、生成记录、历史下载及中英文输出。
- 审计日志、附件、资源导入、错误报告和幂等处理。
- 司机、车辆司机绑定及文档列出的完整 Itinerary Item 类型。
- 后端鉴权、数据权限、事务、金额定点数、安全、监控、备份和恢复。
